# 备份与恢复

本项目提供内容迁入和完整恢复两种流程。当前开发库、管理员密码和现有文件不会在演练中被覆盖。

## 内容包：用于迁入新草稿

在 `/admin/maintenance` 下载 UTF-8 JSON 内容包，可选择是否包含受管图片。当前导出 v7，包含文章、闪念、朋友圈、评论、留言、图库、器材配置、项目、友链及规则、目录与站点资料；兼容旧 v1/v2/v3/v4/v5/v6 迁入。不包含登录凭据、访客控制标识、点赞、回应、修订历史和互动去重记录。v1 仍不接纳朋友圈，v1/v2 不接纳留言，v1/v2/v3 不接纳图库或器材配置，v1/v2/v3/v4 不接纳项目，v1/v2/v3/v4/v5 不接纳友链或规则；各层未知字段和不支持的版本明确拒绝，不静默丢弃。

v7 显式扩展图库 `values.mediaId: string | null` 与 `values.externalUrl: string | null`，两字段均需存在且恰有一种有效来源。v4–v6 仍要求媒体编号，拒绝外链新字段；读取旧包后按媒体来源处理。外链只保留地址及已有作品资料，不抓取远程图片、提取尺寸或生成媒体资产。草稿迁入、跳过/复制、媒体映射、预览变化确认、事务回滚和同票据幂等沿用现有机制。完整恢复在全表摘要之外检查来源互斥、媒体存在及引用；外链不要求虚假媒体引用，旧数据库备份仍可用原有媒体结构恢复。

上传后先校验格式版本、大小、图片真实格式/摘要和引用，再展示明确预览。可选择跳过相同内容（友链按规范 URL 判重）或创建新副本；文章、闪念与朋友圈始终迁入为新草稿。未删除评论关系和审核状态保留，新副本重新累计阅读和点赞。朋友圈的结构化文章关系映射到目标文章；目录遵循目标站点历史别名规则。正文中的普通链接保留原文，发布前需核对。详见[朋友圈维护](backend/moment-maintenance.md)。

站点资料与评论审核设置默认不改动；勾选迁入设置后，预览显示将写入的公开资料，保存产生新的设置历史。执行绑定具体预览摘要，重新预览后旧确认失效。数据库变更统一提交，故障时回滚。票据重复执行返回既有结果，断线后可查询，不能凭响应丢失判断操作未执行。

图库作品使用独立媒体编号，迁入后分配新作品编号并重建媒体引用；媒体 UUID 保持稳定，相同 UUID 的文件摘要冲突会阻止导入，缺少文件时必须补充含图片的包或先恢复媒体。未删除作品无论原状态均迁入为草稿，保留标题、说明、分类、排序、拍摄日期、可选地点/设备及原创建/发布时间；已删除作品跳过，不复活。跳过策略按作品内容匹配，不因目标已变为草稿而重复创建。器材介绍来自独立 `gallery_settings`，最多 12 项；默认保留目标配置，只有勾选迁入设置才展示并应用 v4 及后续版本中的器材资料。旧包不包含器材配置，勾选设置也不会清空目标器材。作品、媒体、恢复上下文或已选择的配置改变后必须重新预览。

留言迁入后，公开和待审项均进入待审状态，隐藏项继续隐藏；删除项作为不可见记录保留，以重建回复关系，不自动恢复媒体引用。全部取消置顶，不迁入回应或原访客凭据。先分配新编号，再映射父留言；混合跳过和复制时同样保留引用。相同内容匹配包含作者、头像、正文、博主标记、删除状态及完整引用语义，不比较审核状态和置顶；循环、缺失引用、重复编号与旧版本携带新字段均拒绝。已完成旧票据可继续查询；未完成旧票据需要重新预览才能执行。

v5 起必须包含 `projects`（没有项目时使用空数组）。项目进展 `active/dev/archived` 与发布状态独立：所有未删除项目迁入为 `draft`，已归档的项目也保留原进展；已删除项目跳过，不复活。标题、介绍、排序、创建/原发布时间、最多 20 个技术标签和最多 4 种链接保留。标签按名称去空白、小写去重，保留首次出现的写法与颜色；同一种链接不可重复，URL 沿用管理接口的 HTTP(S)、无凭据/控制字符/反斜杠校验，不访问外站。封面可明确为空，有封面时复用媒体 UUID 并重建引用。没有可信来源的 Star/Fork 等外部指标不迁入，也不会编造；此类未知字段明确拒绝。

项目跳过判定包含进展、排序、标签顺序/颜色、链接和封面，不比较发布状态；因此同一包迁入的草稿能够被后续跳过策略识别。同包相同内容在跳过策略下仅新建一项，复制策略允许分别创建草稿。项目变更或内容库恢复会使原预览失效。导入事务中项目写入失败会回滚之前创建的文章、图库和媒体记录并清理本次文件；客户端断开后应查询原票据，不能重复创建新任务来猜测结果。

v6 必须包含 `links` 和 `linkSettings: { rules }`，空站点使用空数组。友链保存名称、介绍、规范 HTTP(S) 地址、互斥的受管 Logo 编号或外部 HTTPS Logo 地址、发布状态、推荐、排序及创建/原发布时间。域名与展示头像从这些字段计算，不重复存入包；“已验证互链”等未建立业务来源的字段拒绝。URL 校验与管理接口共用，保留路径大小写、尾斜杠、参数顺序/重复值与片段，不读取外部站点；受管媒体路径即使包装成其他域名的 HTTPS 地址，也必须通过 `logoMediaId` 关联。

友链跳过策略按规范 URL 处理目标和同包重复项，即使介绍不同也保留原记录；预览逐项说明原因。复制策略允许同 URL 新建草稿，保留原地址与推荐/排序，不改写路径或参数来绕过重复规则，不自动上架。已删除友链跳过，不复活；其余状态统一迁入草稿。同一地址至多有一条公开友链，复核后手动上架仍须通过该约束。普通后台创建或改址继续拒绝与任何未删除友链重复，和明确的内容包草稿复制区分。

规则默认保留目标配置。勾选迁入设置后才预览并应用 v6 规则，最多 12 条、每条 1–300 字；旧 v1–v5 包即使勾选设置，也不会清空目标友链规则。目标友链、恢复代次或已选择规则的版本变化会要求重新预览。友链或规则写入失败会回滚同批文章、图库、项目和媒体；断线保留原票据，通过查询确定完成状态，重复执行同一票据不会增殖。

单包最多 50MB、1000 篇文章、2000 条闪念、2000 条朋友圈、2000条留言、3000 件图库作品、2000 个项目、2000 条友链、各域合计10000条评论、300个媒体；包含图片时总解码像素不超过1亿。更大的站点使用完整备份。预览有效期15分钟，完成或过期后清除临时包内容，保留票据摘要和结果。

## 完整备份：数据库与登记媒体

依赖 Node 24、固定版本 pnpm、Docker，以及运行中的 PostgreSQL 16 容器。本地容器默认 `tixxin-blog-postgres`，当前端口映射 15433。可通过 `BACKUP_POSTGRES_CONTAINER` 指定不同本机容器。

在仓库根目录执行：

```powershell
corepack pnpm --filter server-main run backup:full
```

默认在仓库 `.backups` 下创建全新目录。自定义目录必须不存在，建议传绝对路径：

```powershell
corepack pnpm --filter server-main run backup:full --output D:/PrivateBackups/tixxin-20260907
```

目录包含：

- `database.dump`：PostgreSQL custom 格式，包含所有 public 表、历史与认证记录。
- `media/`：所有登记的受管图片，包含回收状态的资源。
- `manifest.json`：格式版本、快照时间、表计数/内容摘要、数据库文件与媒体 SHA-256。

数据库导出使用同一 `pg_export_snapshot` 一致快照；快照固定后的新写入不会混入。媒体按快照中的登记清单复制和校验。文件缺失或摘要不符时不会生成完成清单。没有 `manifest.json` 的目录属于未完成备份。

备份中包含私人草稿及认证哈希，应存放在受控目录。源码、运行环境密钥、人工放入 `public` 的静态文件和外链图片不在数据备份范围，需要按各自来源保管。`.backups` 已从 Git 和 Docker 构建上下文排除。

## 校验与隔离恢复

仅恢复可信来源的备份；校验和用于检测完整性，不能证明来源。

```powershell
corepack pnpm --filter server-main run backup:verify --directory D:/PrivateBackups/tixxin-20260907
corepack pnpm --filter server-main run backup:restore --directory D:/PrivateBackups/tixxin-20260907
```

恢复命令使用本机已有的官方 `postgres:16-alpine` 或 `postgres:16` 镜像，新建专用数据卷和 `tixxin-restore-<UUID>` 容器。容器使用 `network=none`，不暴露网络端口。原数据库、原媒体目录和原容器保留。

恢复过程校验全部表行数与内容摘要，复制并校验媒体，再撤销恢复出来的访问/刷新授权，递增账号会话版本，并轮换内容上下文。密码哈希按备份原样恢复；原库密码不修改。旧页面即使重新登录也必须刷新读取恢复后的内容，不能继续提交旧数据上下文。

完整备份覆盖留言、回复关系、审核/删除状态、回应、媒体引用、提交去重记录和开发样本归属账本。留言公开发送及回应也校验恢复代次：缺少必需上下文返回428，旧上下文返回409；输入保留，重新读取后方可提交。

图库的作品、媒体关系、器材配置、乐观版本、提交去重标识和开发样本归属同样包含在全表一致快照及内容摘要中。恢复后额外校验非删除作品的引用索引、媒体关联、配置存在性与归属编号格式；归属账本允许保留已删除资源的标识，以阻止重复补种复活。图库管理写入沿用恢复上下文保护，旧页面不能向恢复后同编号的作品继续提交。

项目完整恢复保留进展、草稿/公开/撤回/删除状态、技术标签、链接、可选封面、版本、提交去重及归属账本。除全表行数和摘要外，恢复报告还记录 `projectIntegrity`：项目数量、带封面数量、实际媒体引用和样本归属数量，并检查无封面或删除项目没有错误引用。可选生产镜像验收进一步核对公开项目/真实标签覆盖率、后台字段、非公开及删除项不可见，以及同编号项目在旧上下文下拒绝写入、新上下文下允许保存。

友链完整恢复保留 `friend_link`、`link_settings` 及开发归属账本，包括同址草稿与原公开记录、撤回/删除状态、推荐、请求去重、规则和 Logo 关系。`linkIntegrity` 额外校验公开 URL 唯一性、互斥图片来源、有效媒体引用及归属标识。外部 Logo 仅保留地址字符串，远端字节不下载到备份；受管 Logo 按登记媒体清单校验并恢复。生产镜像验收还核对真实公开统计/规则、后台字段、头像投影、不可见状态及新旧内容上下文写入边界。

输出目录包含 `restore-report.json`、`connection.json` 和恢复后的 `media`。`connection.json` 含新隔离数据库的本地配置，仅适用于该隔离容器网络空间，不应发布。恢复命令不会自动修改应用环境。

## 切换与回退

正式切换应由操作者在核对恢复报告后执行：

1. 保留当前库的最新完整备份，停止所有原 API 实例，避免切换期间继续写入旧库。
2. 保留隔离恢复卷，通过受控容器网络连接需要使用它的 API；勿将数据库端口开放到公网。
3. 使用恢复目录中的连接资料配置 API，并将媒体目录指向恢复后的 `media`。使用与备份匹配的代码版本；升级代码时先回放新增迁移并检查 schema。
4. 启动服务并验证 `/ready`、公开文章/图片及管理登录。所有旧登录授权已撤销，管理页面需刷新。
5. 需要回退时停止 API，重新指向保留的原库与原媒体目录。不要直接删除原数据或覆盖备份目录。

完整恢复是备份时刻的数据状态；如果备份之后修改过密码，需要使用备份时的账号资料处理恢复目标。切换不在自动演练范围内。

## 可重复演练与诊断

```powershell
corepack pnpm --filter server-main run test:backup-restore
```

项目内容迁入的独立接口验收在最新后端构建后执行 `node src/backend/server-main/tests/project-backup-integration.mjs`；包含真实请求已经开始后中断客户端、随后核查完成票据及重试不重复，以及项目写入触发故障时跨模块事务回滚。

友链内容迁入的独立接口验收使用 `node src/backend/server-main/tests/link-backup-integration.mjs`，覆盖 v1–v5 兼容、v6 URL 与媒体校验、同址跳过/草稿复制、旧规则保留、友链/规则两类事务故障、真实请求中断后查票据、恢复上下文和零外部抓取。

演练创建随机命名的隔离源库，验证并发新文章不进入既有快照、篡改文件被拒绝、全部表摘要及媒体一致。恢复容器和卷带任务标签，测试只清理自己创建且标签匹配的资源。本次源库、备份副本、恢复媒体及连接资料在结束时清理，仅在本机已忽略的 `.artifacts/backup-restore/verification-*/verification-report.json` 保留不含凭据的报告，不纳入 Git。

后台运行诊断只向管理员展示数据库连通性、待应用迁移、schema 一致性、Node 版本和存储读写探测。媒体完整性核验单独读取登记资源，返回缺失/损坏的资源编号，不公开磁盘路径或连接凭据。

恢复后的媒体目录默认仅归创建用户访问；将其挂载到容器时，需让运行 API 的用户具有读取权限。可设置 `RESTORE_API_IMAGE` 运行当前后端镜像的隔离应用验证；验证会共享恢复容器的无外部网络空间，不发布端口。CI 同时检查数据库、媒体和旧授权拒绝。

使用当前源码的独立生产镜像验收时，可在仓库根目录执行（镜像名应使用本次专用且尚未占用的标签）：

```powershell
docker build -f src/backend/server-main/Dockerfile -t tixxin-backup-restore-test:latest .
$env:RESTORE_API_IMAGE = 'tixxin-backup-restore-test:latest'
corepack pnpm --filter server-main run test:backup-restore
Remove-Item Env:RESTORE_API_IMAGE
docker image rm tixxin-backup-restore-test:latest
```

此流程使用隔离测试账号和媒体，无需提供日常账号密码。应用验收核对生产 `/ready`、公开文章/图库/项目/友链数量、器材与友链规则、项目标签覆盖率、媒体字节摘要、恢复前 token 拒绝、原密码重新登录，以及图库/项目/友链后台字段和原记录一致。还会用恢复前上下文对同编号内容提交并要求返回 409，缺少上下文要求 428，重新读取后使用新上下文允许保存。所有写入只发生在即将清理的恢复副本；实际站点切换、外部网络、生产部署及真机浏览器不在此演练范围内。
