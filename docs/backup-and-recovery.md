# 备份与恢复

内容包用于向站点迁入内容，完整备份用于保留数据库与登记媒体。两者的身份、历史和恢复语义不同；迁入内容不能替代完整灾难恢复。

| 流程     | 包含内容                                                                                                  | 结果                                                   |
| -------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 内容包   | 可迁移的文章、闪念、朋友圈、留言、图库、项目、友链、图片提示词、平台订阅费、评论、目录与可选站点配置/媒体 | 新编号的草稿或待审记录，按明确策略跳过或复制           |
| 完整备份 | 全部 public 表、历史、身份、互动、提交标识、运行状态和登记媒体                                            | 独立数据库与媒体副本；校验后撤销旧授权并暂停外部副作用 |

## 内容包版本

当前导出 **v14**，接受 **v1–v13** 的既有格式。旧版本不能夹带其未支持的新字段，未知字段和不支持版本明确拒绝，不静默丢弃数据。

| 版本 | 引入的格式能力                                 |
| ---- | ---------------------------------------------- |
| v1   | 基础内容格式                                   |
| v2   | 朋友圈                                         |
| v3   | 留言及回复关系                                 |
| v4   | 图库与独立器材配置                             |
| v5   | 项目                                           |
| v6   | 友链与规则                                     |
| v7   | 图库外部图片来源                               |
| v8   | 站点关于资料                                   |
| v9   | 文章/项目/图库有序关系及媒体说明               |
| v10  | 图片提示词、模型、标签及图片来源               |
| v11  | 平台订阅费、完整价格历史与受管图标             |
| v12  | 站点导航、页脚链接、每日一言、备案号与版权文案 |
| v13  | 闪念评论审核状态                               |
| v14  | 站点搜索引擎收录开关                           |

格式校验入口为[content-package.ts](../src/backend/server-main/src/modules/backup/content-package.ts)。升级格式时显式演进版本，保留旧包缺省行为和兼容测试，不重解释已有版本。

内容包不包含登录凭据、访客控制标识、点赞/回应、文章/站点修订历史和互动去重记录；新副本重新累计互动。订阅价格历史属于业务事实，会完整保留。管理员导出的站点资料可以包含隐藏关于字段，文件仍应按其实际内容妥善保管。

## 下载、预览与确认

在 `/admin/maintenance` 下载 UTF-8 JSON 内容包，可选择是否附带受管图片。上传后先校验版本、结构、大小、图片真实格式/摘要及引用，选择 `skip` 或 `copy` 策略，以及是否迁入设置。

默认保留目标站点资料、审核策略、器材和友链规则；只有明确选择迁入设置后才预览并应用。旧包缺少关于、器材或友链规则时，即使选择设置迁入，也不会清空目标已有配置。

预览票据绑定当前管理员、内容上下文、目标状态和具体摘要。执行要求确认文本与 confirmation 匹配该预览；重新预览后旧确认失效。目标内容、媒体、恢复代次或被选配置版本变化时必须重新核对。预览有效期 15 分钟；完成或过期后移除临时包正文，保留票据摘要和结果。

同票据重复执行返回原结果。上传或执行中断后先查询原票据，不能根据响应丢失判断操作未执行，也不能另建任务猜测结果。数据库迁入在事务内提交，任一业务失败会回滚同批内容和媒体记录，并清理本次新文件。

| 上限                                                                          | 范围             |
| ----------------------------------------------------------------------------- | ---------------- |
| 50 MiB                                                                        | 单个包文件       |
| 1000 篇文章、2000 条闪念、2000 条朋友圈、2000 条留言                          | 内容记录         |
| 3000 件图库作品、2000 个项目、2000 条友链、3000 条图片提示词、3000 条平台订阅 | 内容记录         |
| 合计 10000 条评论、300 个媒体                                                 | 关联记录         |
| 1 亿解码像素                                                                  | 包内图片总解码量 |

超过适用规模时使用完整备份，不能通过截断包内容绕过关联校验。

## 迁入语义

文章、闪念、朋友圈、图片提示词及未删除的图库、项目、友链、平台订阅迁入为草稿，不自动公开。已删除作品/项目/友链/平台订阅不复活。留言的公开和待审项迁入为待审，隐藏项保持隐藏，删除项以不可见记录保留用于重建回复关系；留言取消置顶，不迁入原访客凭据或回应。

项目进展 `active/dev/archived` 与发布状态独立；迁入草稿仍保留原进展、标签、用途链接、排序和可选封面。图库保留作品说明、可选拍摄日期/地点/设备和排序，不从上传时间推断拍摄事实。服务端管理的创建与原发布时间按格式保留，后续正常发布仍遵循业务规则。

媒体 UUID 保持稳定，相同 UUID 但字节摘要不同会阻止迁入；缺少文件时需提供含图片的包或先恢复媒体。复用现有媒体不覆盖其元数据或说明。v9 可迁入新媒体 description；旧包的新媒体说明缺省为空。

图片提示词保留完整正向/负向提示词、模型、标签、图片替代文本和来源链接。`skip` 按内容判断相同项，标签顺序和发布状态不影响去重；`copy` 创建新的草稿。同票据重试不会重复创建。迁入不继承编辑版本或原请求凭据，旧版本内容包没有提示词时不改变目标已有条目。

### 关系映射

先为整批新内容分配编号，再映射有向、有序关系及新文章修订快照，不让来源编号误指向目标站点已有内容。跨内容循环关系可以复制，自关联和包外不存在编号按规则拒绝。混合跳过/复制时复用匹配的目标身份；去重形成自身引用时要求改用复制策略。

导出省略已删除或缺失目标，并用 `omittedRelations` 记录实际省略量供预览。完整数据库备份仍原样保留这些失效关系与历史。内容关联不改变媒体引用计数。

留言先分配新编号再映射回复；缺失引用、循环回复和重复编号拒绝。匹配依据包含正文、作者、删除状态及完整引用语义，不因审核或置顶变化制造新副本。普通正文链接保留原文，正式发布前核对目标地址。

### 外链与重复地址

图库 v7 及以后必须明确提供 `mediaId` 和 `externalUrl`，恰有一种有效来源；v4–v6 仍只接受受管媒体。外链只保留地址，不抓取远端文件、尺寸或 EXIF，不创建媒体资产。

图片提示词 v10 必须明确提供 `mediaId` 和 `externalImageUrl`，恰有一种有效来源；外部图片只保留地址，不创建受管媒体。受管图片引用包含草稿，存在引用时不能移除资源。

友链 skip 按规范 URL 判断，保留已有目标，即使描述不同也不覆盖。copy 可创建同址草稿，不自动改参数绕过重复；同一规范 URL 最多一条公开友链。普通后台新建/改址继续拒绝与任何未删除记录重复。

外部地址保留合法路径大小写、尾斜杠、查询参数顺序/重复值和片段，拒绝凭据、控制字符、反斜杠及危险协议。受管媒体地址必须通过 UUID 关联，不能包装成外站地址绕过引用保护。服务器不读取外站或远端 Logo。

### 平台订阅费

v11 要求 `subscriptions` 数组；v1–v10 不允许夹带此字段，读取旧包时缺省为空且不触碰目标站已有订阅。访客 LocalStorage 记录不上传，也不进入站点内容包。

每条订阅包含原币种最小单位金额、周期、业务状态、日期、管理备注、完整价格事件与可选受管图标。价格事件保存稳定 UUID、生效时间、记录时间、新金额/币种/周期和可选原因；解析拒绝重复、倒序、非法金额或日期、未知字段及末条与当前价格不一致，不生成过去的未知价格。

skip 按业务内容和完整历史判断，忽略发布状态及可再生 favicon 缓存信息；相同内容已有删除墓碑也不自动复活。copy 明确创建新编号草稿，已删除源记录始终跳过。迁入保留历史，不继承 `requestId/requestHash/revision`，不因为源记录公开而直接发布。媒体 UUID 必须映射到包内或目标站可用资源；缺失/回收图标阻止执行预览。当前价格、历史、引用和新文件在同一导入事务及现有文件补偿机制下保存，失败后可沿用原票据重试。

### 站点导航与页脚

v12 的 `site` 可携带 `navigation`、`footerLinks`、`quotes`、`icpNumber`、`icpUrl` 与 `copyright`，与后台保存使用同一校验：内置模块白名单且不重复、首页不可隐藏、外链导航最多 4 个且仅限 http(s)、页脚链接最多 8 个（站内路径或 http(s)）、每日一言最多 30 条且不重复。v1–v11 出现这些字段按未知字段拒绝；读取旧包时字段缺省，选择迁入设置也沿用目标站现值，不重置为默认。它们保存在 `site_settings.values` JSON 中，完整备份随该表的行摘要一并保留与核对。

### 闪念评论审核状态

v13 的每条闪念评论必须带 `status`（`published`/`pending`/`hidden`，与朋友圈评论取值一致），缺失或其他值拒绝；v1–v12 出现该字段按未知字段拒绝，读取旧包时闪念评论一律按已发布处理。闪念仍迁入为草稿，评论保留包内审核状态，草稿公开前评论不会对外展示。完整备份中 `flash_comment.status` 随全表行摘要保留与核对，恢复报告的 `flashCommentIntegrity` 另外核对状态取值、所属闪念及各状态数量；没有该列的旧备份只报告缺列，使用新应用前仍须正式迁移。

### 搜索引擎收录开关

v14 的 `site` 可携带布尔值 `searchIndexing`（是否允许搜索引擎收录本站），非布尔值拒绝；v1–v13 出现该字段按未知字段拒绝。v14 包缺省该字段或读取旧包时字段保持缺省，选择迁入设置也沿用目标站现值，不会把已关闭的收录重新打开。该值保存在 `site_settings.values` JSON 中，没有独立列，不需要数据库迁移；读取缺少该键的当前值与历史版本时同样按 `true` 处理，完整备份随该表的行摘要一并保留与核对。

## 创建完整备份

宿主 docker 模式需要已构建后端、Docker 和匹配连接目标的 PostgreSQL 16 容器，可通过 `BACKUP_POSTGRES_CONTAINER` 指定。不要根据示例端口猜测实际数据库。生产 worker 使用 native 模式与容器中的 PG16 客户端，配置见[运行维护](operations.md#自动完整备份)。

```sh
corepack pnpm --filter server-main run backup:full
```

默认在忽略目录 `.backups/` 创建全新子目录。自定义 `--output <完整备份目录>` 必须尚不存在；已有备份不覆盖。后端已构建时，也可直接使用：

```sh
node src/backend/server-main/scripts/full-backup.mjs create --mode native --output <完整备份目录>
```

备份包含 `database.dump`、`media/` 和 `manifest.json`。数据库使用同一 `pg_export_snapshot`，全部 public 表计数/行摘要和媒体登记清单来自同一快照；后续写入不混入。媒体按清单复制并逐个校验字节和 SHA-256，包括回收状态但仍登记的资源。文件缺失或摘要不符时不会产生完成清单，没有 manifest 的目录属于未完成备份。

完整备份包含私人草稿、密码哈希和授权记录，应存入受控目录。源码、运行环境秘密、人工放入 public 的静态文件和外部图片字节不在此数据备份范围，需按各自来源保管。数据库 dump 不能替代媒体备份。平台订阅 favicon 属于可再生缓存，`MEDIA_DIRECTORY/.subscription-favicons/` 不进入登记媒体清单，恢复无缓存仍保留官网域名与完整业务记录；受管图标则按正式媒体备份。受管媒体的宽度变体同样是派生缓存，`MEDIA_DIRECTORY/.media-variants/` 不进入登记清单、完整备份和内容包（内容包只导出 `<媒体UUID>.webp` 原图），恢复后由公开读取按需重新生成。

## 校验与独立恢复

```sh
corepack pnpm --filter server-main run backup:verify --directory <完整备份目录>
corepack pnpm --filter server-main run backup:restore --directory <完整备份目录>
```

只恢复可信来源的备份；校验和能检查完整性，不能证明来源。恢复使用本机已有的 `postgres:16-alpine` 或 `postgres:16`，新建专用卷和 `tixxin-restore-<UUID>` 容器，`network=none`，不发布端口，不覆盖原数据库或媒体。

恢复要求实际 public 表集合与清单精确一致，逐表核对行数和内容摘要，并将数据库完整媒体库存的 UUID、存储键、摘要和字节数与清单逐项比较。遗漏运行表、伪造空媒体清单或错误媒体编号均拒绝；真实旧备份没有新增表时沿用相应兼容流程。

在全表摘要之外，还检查图库/项目/友链/图片提示词/平台订阅费的媒体引用、外链来源互斥、公开友链 URL 唯一性与开发归属关系。归属账本可以保留已删除资源的标识，不因恢复后 seed 而复活记录。外部图片只恢复地址。订阅逐条校验金额、币种、业务日期与完整价格历史，核对当前价格和末条事件一致、图标引用与提交身份；历史事件、软删除记录及开发归属均包含在原始行摘要内。真实旧备份没有订阅表时不要求该表，使用新应用前仍须正式迁移。

验证原快照后才执行恢复安全操作：

1. 撤销恢复出的访问/刷新会话，递增账号会话版本；密码哈希仍为备份时的值。
2. 轮换内容上下文，要求旧页面重新读取，缺上下文返回 428，过时代次返回 409。
3. 轮换运行代次，暂停邮件与自动备份；旧邮件未完成项转 restored，运行中的备份标为中断失败，其余未完成备份转 restored，清除旧租约。
4. 新增独立的 `recoveryVerified` 记录表示恢复校验完成，不把它当成新备份生成成功。

环境开关为 true 也不会绕过恢复后的数据库暂停。旧 restored/uncertain/failed 邮件需明确核对，不能因启用 worker 自动重发，详见[运行维护](operations.md#恢复后启用)。

输出目录包含 `restore-report.json`、`connection.json` 与恢复后的 `media/`。connection 文件包含隔离目标凭据，不应发布；连接仅适用于恢复容器的网络空间。恢复命令不会自动更改应用环境。

## 切换恢复目标

1. 保留当前数据库和媒体的最新完整备份，停止全部原 API 与 worker，避免继续写入。
2. 核对恢复报告，保留恢复卷，通过受控网络连接需要使用它的 API，不开放数据库公网端口。
3. API 同时切换到恢复数据库和恢复媒体目录，确保运行用户具有媒体读取权限。使用匹配版本；升级时先应用新增正式迁移并检查结构。
4. 验证 `/ready`、公开内容、图片和管理登录；使用备份时的账号资料，旧页面刷新后再写入。
5. 需要回退时停止新 API，重新指向保留的原数据库和原媒体。不要删除原数据或覆盖原备份。

如果恢复仅用于演练且不再使用，依据恢复报告核对本次容器、卷与目录归属后再定向清理，特别移除 connection 凭据；不使用全局 Docker prune 或递归删除备份根目录。数据切换与应用镜像回退分别执行，后者见[部署指南](deployment.md#应用回退与数据恢复)。

## 可重复验证

```sh
corepack pnpm --filter server-main test:backup-integrity
corepack pnpm --filter server-main test:backup-restore
corepack pnpm --filter server-main test:integration
node src/backend/server-main/tests/prompts-backup-integration.mjs
node src/backend/server-main/tests/subscription-backup-integration.mjs
```

这些入口使用隔离源库、媒体、账号和恢复容器，验证并发快照、篡改拒绝、关系映射、事务回滚、断线后查票据与恢复上下文。`test:backup-restore` 可设置 `RESTORE_API_IMAGE`，使用已构建后端镜像验证恢复后的就绪、公开数据、真实媒体、旧授权拒绝、新登录与新旧内容上下文写入。 API 演练将已核验媒体复制到本次专用容器，不依赖宿主目录共享，也不修改原恢复目录；遇到生产限流时按真实 `Retry-After` 等待并重试一次，报告中的 `throttleRetries` 记录此类重试次数，全部业务断言仍需通过。

生产式完整路径使用[部署指南](deployment.md#本地编排与隔离验证)中的隔离 HTTPS 演练。测试只清理自身拥有的资源，将不含秘密的记录留在忽略目录；正式目标上的切换、权限与外部网络仍需单独核对。
