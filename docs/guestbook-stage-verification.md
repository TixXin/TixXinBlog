# 开发数据与留言板阶段验收

验收日期：2026-09-09。本阶段实现、日常样本、验证及隔离资源清理均已完成。

## 实际交付

- 开发链路继续使用 Node24、pnpm9.15.0、Nuxt/Vue、NestJS/MikroORM/PostgreSQL。扩展现有 `db:dev`，没有新建另一套业务存储或启动器。
- `check-data` 区分服务/数据库/网关故障、缺少场景和正常筛选空结果。数据目录注明真实API、演示数据和LocalStorage边界。
- `core-v1` 与 `guestbook-v1` 通过归属账本增量补齐；重复执行不复制、不覆盖编辑、不复活删除项。真实点赞和回应有对应明细，图片使用本地媒体并建立引用。
- 留言前台保留聊天/论坛、标题正文边界，完成真实发送、回复、回应、筛选、历史分页及失败重试。草稿按身份和页面用途隔离；未知结果重试沿用提交标识。
- 后台完成分页、日期/状态/正文筛选、回复、审核、隐藏、置顶与删除。隐藏或删除引用不泄露原正文，服务端决定身份、审核和计数。
- v3内容包兼容v1/v2，导入留言保持非公开状态并映射回复；完整备份恢复保留互动、去重、审核与归属。公开留言写入也拒绝恢复前的旧内容上下文。
- 指定样本清理先预览、确认、检查其他连接、备份和锁内复核；有编辑或外部互动的关联内容保留。账本、磁盘图片、账号、站点配置和备份保留。旧朋友圈清理同步保护后来互动。

## 使用与后续边界

```sh
corepack pnpm dev:check
corepack pnpm dev:all
corepack pnpm db:dev check-data
corepack pnpm db:dev seed-data --dataset all
corepack pnpm db:dev remove-data --dataset guestbook-v1
```

最后两条默认仅预览。补齐或指定清理需在核对目标后加 `--apply --confirm 数据库名`；清理前需要正常退出后端/数据库客户端，工具不会停止用户进程。日常库本轮已补齐，无需再次操作。被删除的新样本不会通过重复seed重建，恢复使用备份或在后续功能中建立新种子版本。

前台 `/guestbook`，管理 `/admin/guestbook`，内容包 `/admin/maintenance`。使用规则见[留言说明](backend/guestbook.md)、[数据目录](development-data-catalog.md)和[开发数据库工具](development-database.md)。

项目、图库、友链仍保留可用演示数据，书签继续LocalStorage。后续真实业务开发必须同批提供代表性日常样本、增量种子、隔离验证、维护兼容与能力清单更新；实时消息、在线/已读、云草稿、注册体系和通知渠道未在本轮扩展。
