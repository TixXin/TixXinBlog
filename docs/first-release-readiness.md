## 首发内容与事实边界

首发候选为已有三篇技术文章与一个 TixXinBlog 项目，审阅和维护入口见 [个人内容](personal-content.md)。只使用仓库实现可核实的技术事实；个人判断、经历、联系资料和摄影归属单独确认。候选保持草稿；开发样本不自动进入生产。

内容包与完整备份的用途不同。首发内容应在隔离目标预览并核对编号、关系、媒体和配置边界，再迁入获授权的正式目标，不能把日常开发库整体复制为正式内容。完整备份用于恢复已存在环境，详见 [备份与恢复](backup-and-recovery.md)。

## 发布前的可复现检查

1. 记录确定的 Git 提交，在独立目录新检出；不复制本机 node_modules、构建目录、环境文件或媒体目录。
2. 使用 Node 24、固定 pnpm 与 `corepack pnpm install --frozen-lockfile` 安装，必要配置按模板通过独立环境提供。
3. 执行前后端 Lint、类型、完整单元测试与构建；按实际改动覆盖接口、迁移、内容包、恢复和浏览器流程。
4. 从相同来源构建前端、API、migration、worker 镜像，验证 HTTPS、就绪、迁移失败停止、回退、备份及恢复。
5. 核对运行时地址贯穿 canonical、分享、RSS 和 sitemap；检查公开状态与失败反馈，原始产物留在本机忽略目录。
6. 检查新检出无意外跟踪产物，清理本次隔离资源；保留日常开发服务和数据。

当前 CI 定义位于 `.github/workflows/`。本机运行通过与云端 CI 通过分别记录；没有执行推送时不声称云端验收已完成。完整集成后仅对后续受改动影响的部分重验。
