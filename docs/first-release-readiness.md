# 首发准备与仓库维护

本入口记录首发内容选择、干净检出、发布验收和日常观察方法。当前任务为2026-09-11仓库整理与首发准备，正在集成验收；本机准备和正式上线分别记录。称呼已确认 `tixxin`，尚未确认的个人资料保持隐藏，生产部署与真实外部通道尚未启用。

## 维护入口与仓库边界

先阅读 [当前能力](capability-map.md)、[架构](project-architecture.md)和[目录](directory-structure.md)，开发使用 [运行自检](development-runtime.md)，发布使用 [发布操作](release-operations.md)。历史设计和阶段结论集中在 [历史归档](README.md#历史交付与设计背景)，不作为当前默认实现说明。

Git 保留源码、正式测试、锁文件、迁移及快照、必要补丁、配置模板、种子素材与许可证、共享工具规则和必要文档。个人工具权限、运行记忆、数据库备份、运行媒体、覆盖率和原始验收产物留在本机忽略目录。详见 [验收产物约定](verification-artifacts.md)。Git 跟踪范围与 Docker 构建上下文分别维护；历史对象体积不因普通清理提交自动减少。

开发配置分别从前后端目录的 `.env.example` 准备，生产配置使用 `deploy/production.env.example` 的仓库外副本。旧根目录环境模板已移除，以免将生产缺省误用于本机开发。旧 `pnpm clear` 会删除锁文件并清理共享 pnpm store，现已移除；正常依赖复现使用固定锁文件安装，不通过删除锁文件处理仓库整理。

## 首发内容与事实边界

首发候选为已有三篇技术文章与一个 TixXinBlog 项目，审阅和维护入口见 [个人内容](personal-content.md)。只使用仓库实现可核实的技术事实；个人判断、经历、联系资料和摄影归属单独确认。候选保持草稿；开发样本不自动进入生产。

内容包与完整备份的用途不同。首发内容应在隔离目标预览并核对编号、关系、媒体和配置边界，再迁入获授权的正式目标，不能把日常开发库整体复制为正式内容。完整备份用于恢复已存在环境，详见 [备份与恢复](backup-and-recovery.md)。

## 发布前的可复现检查

1. 记录确定的 Git 提交，在独立目录新检出；不复制本机 node_modules、构建目录、环境文件或媒体目录。
2. 使用 Node 24、固定 pnpm 与 `corepack pnpm install --frozen-lockfile` 安装，必要配置按模板通过独立环境提供。
3. 执行前后端 Lint、类型、完整单元测试与构建；按实际改动覆盖接口、迁移、内容包、恢复和浏览器流程。
4. 从相同来源构建前端、API、migration、worker 镜像，验证 HTTPS、就绪、迁移失败停止、回退、备份及恢复。
5. 核对运行时地址贯穿 canonical、分享、RSS 和 sitemap；检查公开状态与失败反馈，原始产物留在本机忽略目录。
6. 检查新检出无意外跟踪产物，清理本次隔离资源；保留日常开发服务和数据。

当前 CI 定义位于 `.github/workflows/`。本机运行通过与云端 CI 通过分别记录；没有执行推送时不声称云端验收已完成。完整集成后仅对后续受改动影响的部分重验。

## 实际启用与日常观察

实际启用需明确域名、部署位置、镜像来源、数据库/媒体/备份持久化、SMTP收件人和异地接收目标。配置示例中的地址不代表已确认归属。发布预检默认只读；执行命令与回退、恢复的边界见 [发布操作](release-operations.md)和[运行通知](operations-and-notifications.md)。

连续使用时记录发生问题的时间、页面/内容编号、操作、期望和实际结果；不要把凭据、私人正文或原始请求头放进公共问题报告。按以下实际流程收集反馈：

| 观察范围   | 记录内容                                                  | 处理入口                         |
| ---------- | --------------------------------------------------------- | -------------------------------- |
| 写作       | 创建到保存的阻碍、恢复冲突、章节定位、素材和关联查找      | `/admin/posts`、`/admin/media`   |
| 阅读       | 手机溢出、图片加载、搜索未命中、分页/返回和关联落点       | `/search`、文章/项目/图库        |
| 互动       | 待审/回复数量与列表是否一致，通知已读与业务状态是否准确   | `/admin`、`/admin/notifications` |
| 运行       | API错误、最近成功备份、失败任务、容量和恢复记录           | `/admin/operations`              |
| 发布后性能 | 真实设备和网络下的加载/交互，区分冷缓存、热缓存和实验结果 | 浏览器性能工具及现有日志         |

两到四周使用是后续观察周期，本轮不等待时间流逝或生成虚构反馈。性能基线与局限见 [性能维护](performance-maintenance.md)。Search Console、域名验证、统计接入、长期计划任务以及真实外部发送按对应授权执行；不承诺收录或排名。书签云同步、访客订阅、友链申请依实际需求另行排期。
