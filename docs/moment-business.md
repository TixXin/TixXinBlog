# 朋友圈真实业务

公开订阅 `/moments.xml` 和 `/api/moments.json` 读取真实公开 API，使用运行时站点地址及站点资料，按发布时间稳定返回最新30条；旧置顶不会挤占最新动态。草稿、归档与撤回不输出，来源失败返回503，不回退示例或缓存旧内容。JSON保留公开聚合字段，不包含评论或私人点赞状态；RSS保留安全正文、主题和首图。开发种子仍可显式读取历史样本文件，公开接口不依赖它。

朋友圈公开入口为 `/moments`、`/moments/:id` 和 `/moments/topic/:name`，通过同源 `/api/v1/moments` 仓储读取真实数据。运行时不加载朋友圈 Mock，也不会在接口失败后回退为演示内容。

## 阅读、筛选与互动

每批读取15条动态；“加载更多”和自动追加共享 `page` URL，刷新时恢复之前页的内容。`q`、`topic`、`date` 与分页由同一 URL 状态控制，搜索防抖，日期使用 UTC。筛选失败保留此前内容并明确提示重试，不将失败显示成真实空列表。缓存按读取时序接收响应，旧分页数据不会覆盖新确认的点赞或评论，删除后的缓存也不会被迟到请求复活。

作者资料来自站点配置，动态、点赞、公开评论、话题、日历和照片来自真实聚合；统计未能读取时显示未知或上次成功结果及错误反馈。三主题沿用已有侧栏归属和信息抽屉，标题/正文区域保持独立过渡。

点赞按当前设备的访客标识在服务端确定身份和计数，提交目标状态而非反复切换。刷新后会补取设备个人状态。访客评论使用已有身份表单、限流和站点审核策略，待审评论仅当前访客与博主可见；博主回复身份由服务器决定。正文输入、评论提交和列表错误均不会被伪装为成功。

评论草稿在当前应用会话内跨页面切换保留，发送失败保留正文及提交标识；重复发送同一请求只保存一次。发送期间继续输入的新正文不会被迟到成功清空。刷新或关闭仍有评论输入的页面时会请求浏览器离开确认，评论草稿不作为已保存内容持久化。退出或切换账号时清理互动会话中的私有信息。

登录尚未确认时，评论发送会保留输入并提示稍后重试，避免把博主操作误作为访客提交。快速刷新中断Cookie轮换时，认证请求继续完成，新页面等待短期协调标记后确认会话；标记不包含账号或令牌。

## 博主管理

登录后使用 `/admin/moments` 管理列表，`/admin/moments/new` 创建，`/admin/moments/:id` 编辑。支持草稿、发布、归档、置顶、删除、话题/日期/正文检索、分页、评论审核、删除及博主回复。

配图使用原媒体上传/选择器；站内引用通过公开文章搜索选择，外链通过明确字段填写。服务器随编辑和删除维护媒体引用。未授权用户不能操作管理 API。

编辑携带服务端版本；并发冲突保留本机输入并展示服务器版本，不自动覆盖。创建使用唯一提交标识，未知结果重试不会重复创建。编辑器在当前标签页的 `sessionStorage` 中保存未提交输入恢复副本，恢复需要手动确认；它不是服务端草稿，也不跨浏览器共享。保存草稿才会持久化到数据库。
