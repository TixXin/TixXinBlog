# 开发数据库工具

新增 `prepare-profile` 仅整理未编辑的初始个人资料；默认预览，写入仍需 `--apply --confirm 数据库名` 和完整备份，已编辑资料跳过。事实内容候选用独立 `editorial-v1` 数据集，3篇文章与1个项目全为草稿。见 [个人内容](personal-content.md) 与 [开发数据目录](development-data-catalog.md)。

本轮另有 `writing-v1`（6条归属）和 `notifications-v1`（71条归属），分别支持 `check-data --domain writing` / `--domain notifications`；补种幂等且先备份。通知样本强制暂停外部投递，清理保护当前及历史内容关联、媒体和通知任务依赖。见 [最终验收](sustainable-blog-verification.md)。

图库外链另有 `gallery-external-v1` 增量集（4作品、无新增媒体资产），支持同一 `seed-data/remove-data` 流程；`check-data --domain gallery-external` 独立核对。原 `gallery-v1` 不被替换或扩写。日常库两种来源均长期保留，具体数量、备份及命令见 [本轮验收](gallery-external-admin-verification.md)。

根目录使用 `corepack pnpm db:dev`，沿用后端进程环境 → `.env.local` → `.env` 的配置顺序。所有命令默认只预览，输出数据库名、服务地址、表计数、作用范围和待应用迁移，不显示用户名或密码。

| 命令                | 明确加上 `--apply --confirm 数据库名` 后的行为                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`            | 始终只读，不接受写入参数                                                                                                                    |
| `seed-moments`      | 追加18条朋友圈开发样本及评论；首次日期平移到今日UTC及近期，正文使用自然内容，内部稳定编号避免重复，已有记录及日期不覆盖，点赞从零开始       |
| `normalize-samples` | 仅去除已登记朋友圈样本正文开头的旧 `[开发示例]` 标记和一个分隔空格；保留人工编辑的其余正文、其他字段、日期及互动，重复执行不产生变化        |
| `remove-samples`    | 识别旧朋友圈样本的稳定编号、修订号、正文和原始互动；已有人工编辑、新增点赞或评论变化的整条动态保留                                          |
| `clear-moments`     | 清空全部朋友圈及其互动、删除记录和提交标识，保留其他业务                                                                                    |
| `clear-content`     | 清空文章、闪念、朋友圈、留言、图库、项目、友链及关联互动、目录和导入票据；保留账号、站点/审核/器材/友链规则设置、媒体库、样本归属账本和审计 |
| `reset`             | 在事务中删除应用表及已登记枚举，重放全部迁移，恢复默认配置；账号、内容、配置历史、媒体索引均被清空，需要重新创建管理员                      |

例如先执行 `corepack pnpm db:dev seed-moments` 查看预览，确认目标确实为 `tixxin_blog` 时，可执行 `corepack pnpm db:dev seed-moments --apply --confirm tixxin_blog`。样本只用于显式开发用途，真实前台始终读取 API，不以接口故障触发样本加载。

日常开发库必须保留正在开发功能的代表性样本，这与自动验收的隔离临时库不同。切换真实 API 时要实际补种并验证页面与侧栏，不能只交付种子命令或只在临时库中验证。现有样本被人工编辑后，重复 seed 不会重置内容、日期或互动；日期平移仅在首次插入时发生。

已有朋友圈正文的旧标记可先通过 `corepack pnpm db:dev normalize-samples` 预览，再以 `corepack pnpm db:dev normalize-samples --apply --confirm tixxin_blog` 写入已核对的本机目标。该操作只匹配种子脚本登记的精确稳定编号，不按编号前缀批量处理其他记录，也不替换正文中间出现的文字；开发用途说明保留在脚本注释和维护文档中。

正文标记清理可在后端运行时执行，在事务内以原正文和修订号作比较更新。备份期间被其他客户端编辑的记录会跳过并报告实际处理数量；再次预览可检查剩余标记。清理不改写修订号、创建/更新/发布日期、评论、点赞或内容上下文，刷新页面即可看到结果。

写入只允许本机非生产数据库，并检查迁移全部应用且实体与结构一致。每次实际写入前通过已有完整备份流程创建 `.backups/` 备份；备份失败则不写入。无须追加、去除标记或删除的样本操作直接结束。备份需要 Docker 中的 PostgreSQL 16 与配置端口匹配，默认容器为 `tixxin-blog-postgres`，可通过既有 `BACKUP_POSTGRES_CONTAINER` 配置指定。维护运行时需要已有后端构建；缺少时先运行 `corepack pnpm --filter server-main build`。

清空和重建要求其他数据库客户端已断开，包括后端服务。工具不会主动终止任何现有进程。正常退出 `dev:all` 后，如果后端是被复用的独立服务，还需要在其原终端正常退出。操作前后重新核对连接，并在事务中取得应用表锁；冲突会失败，不会无限等待或重复执行。`reset` 不使用 `CASCADE`，应用表之外的依赖会阻止重建并回滚。

清空和重建轮换内容上下文，旧页面不能继续提交旧内容。操作成功后重新启动服务并刷新页面。`reset` 后可按已有管理员初始化流程显式执行 `corepack pnpm --filter server-main seed:dev`，需要通过环境配置提供符合要求的管理员密码；该既有命令同时加入文章和闪念开发数据。

工具不会删除磁盘上的媒体文件，也不会改写环境文件或删除备份。`reset` 后原媒体文件可能不再有数据库索引，完整备份保留其恢复依据。需要恢复原账号、配置及内容时，使用既有完整备份恢复到新目标的流程，不能把再次 seed 当作恢复。

## 按归属管理新样本集

`db:dev check-data` 核对开发链路与场景；`db:dev seed-data --dataset core-v1|guestbook-v1|gallery-v1|project-v1|link-v1|all` 预览增量补齐，写入仍需 `--apply --confirm 数据库名`。目录和数量见 [开发数据目录](development-data-catalog.md)。

`db:dev remove-data --dataset core-v1|guestbook-v1|gallery-v1|project-v1|link-v1|all` 只预览，输出每条可移除归属及保留原因。实际清理须正常退出后端与数据库客户端，再加 `--apply --confirm 数据库名`；它不会结束其他进程。先备份，随后取得应用表锁并重新核对整个计划，范围变化就退出而不删除。

只移除指定组内指纹未变的内容。用户编辑、外部回复/回应/点赞、另一组数据或其他引用会保护相关内容家庭；媒体仍被保留内容引用时，不移除索引。图库、项目、友链的直接媒体外键与统一媒体引用同时核对，同一图片仍被手工维护的作品、其他业务或文章历史修订使用时保留图片索引。派生的文章地址、修订、标签关联和媒体引用随可移除内容清理；目录本身、用户账号与配置保留。未知关联采用保留处理。

归属账本始终保留，因此被人工删除或经 `remove-data`/`clear-content` 删除的新版样本不会在重复补种时复活，检查会报告缺失。需要恢复时使用完整备份；新增开发场景应建立新的种子版本，不靠删除账本重写既有数据。磁盘媒体文件保留供恢复，未引用文件不再作为活动资源展示。自动化清理验证只在临时库执行，日常开发样本继续保留。

验证命令为 `corepack pnpm --filter server-main test:database-dev`。它只使用随机临时数据库、临时媒体和测试账号，验证只读预览、目标/生产/运行连接拒绝、真实备份、自然正文种子与旧标记清理幂等、并发更新跳过、编辑内容/日期/互动与非样本保留、新旧样本定向删除、清空与迁移重建，然后清理隔离数据库和媒体。不会清空当前开发数据库。

开发数据回归 `test:development-data` 包含核心、留言、图库、项目、友链和定向清理；这些测试与 `test:database-dev` 都将真实完整备份输出到 `.artifacts/database-fixtures/run-*/` 的本次独立目录，最终清理完整备份与失败半备份，不向日常 `.backups/` 积攒测试资源。清理图库、项目与友链内容保留器材和友链规则配置、媒体索引与样本账本；全部重建则通过正式迁移恢复默认空器材与友链规则配置。
