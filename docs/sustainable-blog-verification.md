## 维护、备份、发布和通知命令

日常使用下列根目录命令；检查只读，启动不隐式迁移或补种：

```powershell
corepack pnpm dev:check
corepack pnpm dev:all
corepack pnpm db:dev status
corepack pnpm db:dev check-data
corepack pnpm db:dev seed-data --dataset writing-v1
corepack pnpm db:dev seed-data --dataset notifications-v1
corepack pnpm --filter server-main backup:full
corepack pnpm --filter server-main backup:verify --directory D:/Projects/TixXinBlog/.backups/backup-1789123595051-75bcc61e
```

补种默认预览，确认本机开发目标后使用 `--apply --confirm tixxin_blog`，实际写入先完整备份。`backup:restore --directory <完整备份>` 沿用独立目标恢复流程，不能将它当作在日常库原地重置命令。后台内容包从 `/admin/maintenance` 预览和确认导入，具体入口以管理导航为准。

生产版本、私有配置文件、域名及备份目录由部署者填入。以下发布命令默认预检，不执行部署；全新安装使用 `--initialize`。已获具体目标授权后才附加 `--apply`：

```powershell
node scripts/release/release.mjs --env-file D:/PrivateConfig/blog-production.env --version <已构建版本> --origin https://blog.example.com
```

邮件/备份操作在已构建的后端目录执行，配置通过仓库外环境文件注入。先读取真实revision，再预览启用；示例revision不可盲目沿用：

```powershell
node --env-file=D:/PrivateConfig/blog-worker.env scripts/operations.mjs status
node --env-file=D:/PrivateConfig/blog-worker.env scripts/operations.mjs enable --kind mail --revision <当前版本>
node --env-file=D:/PrivateConfig/blog-worker.env scripts/operations.mjs enable --kind backup --revision <当前版本>
```

对应授权后加 `--apply`；可单次执行 `schedule --apply` 和 `run-once --kind mail|backup --apply`。长期执行还需 `OPERATIONS_WORKER_ENABLED=true` 并显式 `loop --apply` 或启用Compose worker profile。SMTP目标、传输URL/token/归属、限频和保留策略见 [运行通知文档](operations-and-notifications.md)。应用回退要求人工确认数据库兼容，脚本不执行down迁移；数据库恢复与向前修复是独立操作。

新增依赖 Nodemailer 10.0.3（类型包8.0.1）服务于标准SMTP，禁用文件/URL读取、只投递最小必要内容；需要随依赖审计维护。运行器复用现有数据库，无新增独立消息队列平台。

## 性能依据与结果

同一隔离数据库，原有106篇加30篇每篇102,555 UTF-8字节长文和3条私有状态，共139篇；3轮预热、20次配对。多标签列表24行的驱动对象JSON从 **5,834,932降到9,736字节（约99.83%）**，HTTP业务JSON仍为5,044字节，逐字段及hash一致。

| 服务方法中位耗时 | 优化前   | 优化后  |
| ---------------- | -------- | ------- |
| 文章列表         | 36.05ms  | 4.30ms  |
| 正文检索         | 105.24ms | 41.28ms |
| 第二页列表       | 37.41ms  | 4.32ms  |

收益来自省去列表不使用的正文与重复取回；正文搜索仍扫描真实正文，不声称新增全文索引或改变搜索复杂度。以上为服务方法及数据库驱动结果，**不是HTTP端到端或浏览器提升**。

另有生产构建后台基线（1次预热、3次采样）：工作台143.8ms、文章列表122.8ms、81,991字节长表单174.1ms，输入到第二个动画帧30.6ms。缓存命中时脚本传输为0但解码约1MB，不解释为无需脚本。这组没有优化前对照，不能计入提升比例。公开页面基线、EXPLAIN、环境和进一步优化边界见 [性能与维护](performance-maintenance.md)。
