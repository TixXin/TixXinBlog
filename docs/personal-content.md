# 站点定位与首发内容

公开称呼只确认了 `tixxin`。默认内容定位为技术写作，项目和图库辅助展示，生活保留独立入口。职位、教育经历、技能熟练度、联系方式、兴趣、书单和摄影经历没有获得确认，保持缺省或隐藏。

## 当前资料边界

| 内容                                   | 可核查依据                                       | 维护方式                                 |
| -------------------------------------- | ------------------------------------------------ | ---------------------------------------- |
| 称呼 `tixxin`                          | 用户明确回复                                     | `/admin/site` 统一维护首页、侧栏与关于页 |
| 技术写作、项目与图库辅助、生活独立入口 | 本轮采用的内容组织                               | 不是个人履历，不补造经历或成绩           |
| TixXinBlog 项目能力                    | package.json、业务代码、Git remote、当前能力清单 | 下文四份首发候选                         |
| 其他项目、生活记录、图库样本           | `development_fixture` 与各域种子                 | 留在开发环境，不作为用户成果迁入生产     |
| 第三方图片                             | 图库素材说明、外链来源及许可证                   | 不写成博主原创，不推测拍摄信息           |
| 个人联系方式和肖像                     | 尚无确认                                         | 不从仓库域名、Git remote 或示例头像推断  |

关于页真实资料在 `/admin/site` 维护。栏目与条目分别显隐，公共 API 剔除隐藏内容；空白或未确认资料不需要用示例填满。站点配置的版本、恢复与历史仍沿用原有保护。

全新数据库也有安全缺省：迁移 `20260911225000_sanitize_initial_profile` 仅处理完整未编辑的旧默认及匹配历史，新增安全版本 1，保留原版本 0；职位与社交为空，头像为 `/avatar.svg`，关于页空白隐藏。手工修改、已有新版本或不匹配历史均跳过，迁移回退不重新公开旧占位资料。

```sh
corepack pnpm db:dev prepare-profile
corepack pnpm db:dev prepare-profile --apply --confirm tixxin_blog
```

这项工具只整理精确的未编辑初始资料。已有日常介绍会跳过；需要修改时，使用后台按已确认事实维护。备份之后仍在写锁内复核，手工 SQL 未递增版本的改动也不会被覆盖。

## 四份首发候选

候选定义在 `src/backend/server-main/src/seeders/editorial-content.ts`，使用原有 `editorial-v1` 归属，不增加一套重复内容。当前均保持草稿，以下地址是授权公开后使用的来源 slug；迁入时如存在地址冲突，以预览和目标最终地址为准。

| 稳定身份                  | 内容                                 | 公开后入口                                        | 重点                                                        |
| ------------------------- | ------------------------------------ | ------------------------------------------------- | ----------------------------------------------------------- |
| `post/content-boundaries` | TixXinBlog 的内容边界与页面职责      | `/articles/tixxinblog-content-boundaries`         | 页面/领域/API、持久化与本机边界、三主题、六域搜索和公开关联 |
| `post/editing-recovery`   | 保存失败之后，如何保住正在写的内容   | `/articles/tixxinblog-editing-recovery`           | 版本冲突、本机恢复、响应丢失、章节定位和维护上下文          |
| `post/backup-boundaries`  | 内容迁入包与完整备份分别解决什么问题 | `/articles/tixxinblog-content-package-and-backup` | v9 迁入、首发清单、完整性/传输/恢复、旧队列暂停             |
| `project/tixxinblog`      | TixXinBlog：技术写作与内容维护       | `/projects?project=<目标编号>`                    | 可核查技术栈、内容能力、维护能力与未实现边界                |

三篇文章均属于“博客建设”专栏，类别为技术，标签为 `TixXinBlog`、`工程实践`。第一篇预设置顶；置顶草稿仍不公开，只有博主明确发布后才进入首页精选。项目进展为维护中，发布状态仍为草稿，两者分别表达含义。

四份内容各有 3 条有序关联，总计 12 条。文章先引导到另外两篇技术文章，再到项目；项目按内容边界、编辑恢复、备份边界的顺序链接三篇文章。关联只保存类型与编号，迁入后重新映射，不在正文硬编码开发数据库 ID。自动专栏/标签推荐继续保留。

正文参考当前检出的具体代码路径和现有维护文档，没有把本机实验数字写成线上收益，没有访问量、用户规模、商业成绩或个人任职表述。GitHub 仓库链接来自已核实的 Git remote，仅作为项目源码入口，不等于确认了个人社交资料或任何域名所有权。

### 媒体与目录依赖

- 三篇文章没有封面、受管图片或外部图片引用；项目没有封面。
- 首发内容媒体依赖为 **0**，没有图片下载或第三方摄影署名问题。
- 内容包只需要“博客建设”一个栏目和两个文章标签；项目自身的 Nuxt、NestJS、PostgreSQL 标签随项目保存。
- 图库仅作为站点的辅助内容入口，本轮四候选不自动选择任何图库样本。

## 更新已有候选时如何保护编辑

普通 `seed-data` 仍不覆盖已有归属，不复活删除记录。全新安装首次创建完整四候选时，会通过原有版本化服务为这四项接线；如果只是补齐部分候选，不会擅自改动已存在的项。

```sh
corepack pnpm db:dev seed-data --dataset editorial-v1
corepack pnpm db:dev seed-data --dataset editorial-v1 --apply --confirm tixxin_blog
corepack pnpm --filter server-main editorial:prepare status
corepack pnpm --filter server-main editorial:prepare refresh
corepack pnpm --filter server-main editorial:prepare refresh --apply --confirm tixxin_blog
```

`status` 与不带 `--apply` 的 `refresh` 只预览。写入仅允许精确确认的本机非生产库，先完整备份，再在原有分类、媒体和样本锁内重读。四项必须全部匹配冻结初稿或当前审阅版本，才能整体迁正：

- 归属键、实际记录、完整行指纹与确切修订版本匹配。
- 文章另行核对标签，以及当前修订的完整快照与历史原因，避免漏掉关联表或历史的手工变更。
- 项目核对原创建指纹和当前内容；不改旧创建记录。
- 备份期间有改动时整批停止，保留用户当前内容和已经完成的备份。
- 任一候选被编辑、删除或缺少归属时，不覆盖、不新建替代、不补造缺失目标；先人工审阅。
- 更新仍使用原编号，新增文章修订并更新对应内部归属指纹；重复运行不再修改。

冻结旧稿位于 `editorial-initial.ts`，仅供精确识别已有日常候选，不能当成新稿继续维护。浏览、点赞和评论计数不作为内容迁正对象；它们不会被重置。

## 生成合法的 v9 首发子包

现有后台导出是全量内容包，没有逐条勾选导出器。专用工具复用现有导出快照和解析器，按四个已核查的归属编号构建子包，不复制日常数据库：

```sh
corepack pnpm --filter server-main editorial:prepare export
```

默认写入新建的 `.artifacts/first-release/content-<UUID>/`，返回 JSON 包和相邻审阅清单。也可以用 `--output` 指定仓库 `.artifacts/` 内尚不存在的 JSON 文件；不会覆盖同名产物。源配置、日志、通知、运行队列、开发归属账本和账号不进入包。

子包包含且只包含 3 篇草稿、1 个草稿项目、12 条内部关联、必要栏目/标签，评论及其他内容域全部为空，媒体列表为空。源站点资料、隐藏关于信息、公告、审核策略、器材与友链规则均丢弃。

**v9 格式要求配置键存在，不能物理删除这些字段：** 子包的 `site` 只使用 `tixxin` 和空白中性值，`requireCommentApproval=false`，`gallerySettings={gear:[]}`，`linkSettings={rules:[]}`。这些仅是格式占位，不代表来源或正式运营配置。迁入必须关闭“包含配置”，即 `includeSettings=false`；已有目标配置保持原样。

### 迁入与公开的顺序

1. 在隔离目标的 `/admin/maintenance` 上传子包，关闭“包含配置”，先审阅预览。首次迁入选择复制为新草稿；已迁入内容再次核对可选择跳过相同内容。
2. 核对计划只新增 3 篇文章和 1 个项目，没有评论、媒体或其他域内容；确认票据后执行。
3. 按结果编号打开草稿，检查标题、摘要、栏目、源码链接和有序关联。来源编号与目标编号不同是正常情况。
4. 在隔离环境可以逐项公开演练：首页只有首篇置顶候选、栏目包含三篇文章、文章与项目之间关系可往返。正式目标未经授权，不执行这一步。
5. 正式站点资料、域名、联系方式与首页介绍另外在目标后台维护，不能靠候选包覆盖。

首页/关于页可审阅介绍仍是：**技术笔记、项目实践与生活记录。** 详细定位说明可写为：这里主要记录 Web 技术实践，整理 TixXinBlog 的实现与维护过程。项目用于介绍具体实现，图库用于整理图片与来源，生活记录保留独立入口。这是内容方向，不是代写的个人履历。

## 验证与当前发布状态

```sh
corepack pnpm --filter server-main test:editorial-preparation
```

专项测试先在独立来源库构造冻结旧稿，验证迁正、备份、版本/历史及编辑删除保护，导出子包后清理来源库；随后在另一个隔离库实际解析、预览、迁入，检查配置不变、12 条关系重新映射、同票据幂等和跳过重复，再只在该隔离库公开验证首页精选、栏目与阅读路径。测试资源由各自 fixture 清理。

本轮具体命令、内容清单、产物和验证结果放在本机 `.artifacts/first-release/content-review.md`；源码和正式回归保留 Git。上一阶段能力交付可追溯至 [持续运营建设验收](archive/sustainable-blog/sustainable-blog-verification.md)，其历史数字不是本轮发布验证结果。

已确认的个人事实仍只有称呼 `tixxin`。首发内容是基于仓库事实的可审阅候选，用户个人观点或实际经历需要自行补充确认；联系方式、肖像及履历没有被补造。日常样本继续留在开发环境。**首发准备和隔离公开演练不等于正式上线，也没有授权真实邮件、异地上传或长期任务启用。**
