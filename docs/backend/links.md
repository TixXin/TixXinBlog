# 友链维护

名称、介绍和规则长度与HTML `maxlength`及既有内容包保持相同的UTF-16计数，合法边界可原样导出再导入；超限写入拒绝，不截断内容。

友链范围为博主管理和公开展示。前台 `/links`，后台 `/admin/links`、`/admin/links/new`、`/admin/links/:id`，规则配置 `/admin/links/settings`。公开申请、邮件通知、自动探活和站点资料抓取均未开放；页面中的资料整理与复制不会向博主提交申请。

## 字段与发布

友链使用稳定整数编号，支持名称（80字符）、介绍（300字符）、完整站点地址（规范化后最多2048字符）、可选Logo、推荐、排序及发布状态。`draft`为草稿、`published`为上架公开、`withdrawn`为下架；推荐独立于发布，不表示已验证互链。排序为推荐优先，再按`sortOrder DESC, id DESC`，排序值范围±1000000。

头像可选择或上传媒体库图片，或填写外部HTTPS图片地址，也可以不设置。两个来源互斥；从媒体库切换到外部地址时明确清除原媒体关联。受管图片的宽高来自实际文件，外部图片没有已知尺寸时保留缺省。保存友链不会请求站点地址或外部Logo；图片由浏览器显示，完整备份只保留外部地址，不复制外站文件。

域名由规范化地址的`URL.host`推导，不能单独填写伪造。公开DTO只提供展示字段，不含发布管理状态、修订号、提交标识、存储键或删除信息。公开接口只读未删除的上架记录。媒体沿用站点既有公开文件边界，友链下架不等于文件私有。

## 地址与重复处理

服务端仅接受完整HTTP(S)站点地址，拒绝凭据、占位符、空白、控制字符和反斜杠。规范化协议、主机名及默认端口，同时保留路径大小写、尾斜杠、参数顺序及重复参数、片段；同域不同页面可以分别登记。

普通新建与改址会检查所有未删除友链中的相同规范化地址，重复返回400并说明已有记录编号。输入保留后可修改地址重新提交，不把已知验证失败当作未知写入结果。相同`requestId`和相同内容的重试仍返回原记录；已使用标识配不同内容或已删除提交返回409，需要先核查原提交。

内容包使用“复制”可保留同地址的新草稿，以便人工复核。草稿可以继续编辑，但同一规范化地址同时只允许一条上架记录，数据库也有相应唯一约束。上架副本前应改址或先下架原记录。导入不会自动更改地址参数来避开重复，也不会自动启用友链。

## API与配置

统一前缀`/api/v1`：

| 路由                                      | 用途                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------- |
| `GET /links`                              | 公开列表；q搜索名称/介绍/地址，featured=true或false筛选，page/pageSize分页 |
| `GET /links/:id`                          | 公开友链投影，非公开记录404                                                |
| `GET /links/metadata`                     | 实际公开links/featured/domains统计与规则rules                              |
| `GET/POST /admin/links`                   | 博主列表/新建，列表另支持status筛选                                        |
| `GET/PATCH/DELETE /admin/links/:id`       | 读取/编辑/删除；修改及删除携带revision                                     |
| `GET /admin/links/submissions/:requestId` | 查询未知创建结果或删除墓碑                                                 |
| `GET/PATCH /admin/links/settings`         | 独立规则与revision，冲突保留输入后重新读取                                 |

默认每页12项，最大48项，页码1–10000。推荐数和不同域名数都来自实际公开明细；同域不同路径各计一条友链、同一域名只计一次。

规则配置`link_settings`包含最多12条非空文字，每条最多300字符。默认空，不虚构申请审核时限。独立规则与真实统计来源分开；本站名称、介绍和头像复用站点设置，本站地址复用`runtimeConfig.public.siteUrl`。读取真实站点资料失败时不能复制预置默认值冒充当前配置。

管理写入沿用账号、内容上下文、审计、提交去重和版本冲突保护；媒体引用与内容事务共用锁。删除保留去重墓碑，释放当前友链引用；仍被图库、项目、文章或历史内容使用的图片继续受保护。

## 开发数据与维护

`link-v1`是独立版本化样本集。补种、检查、定向清理使用既有数据库工具；实际数量与交付证据以[阶段记录](../archive/content-history/gallery-project-link-stage.md)和[开发数据目录](../development-data-catalog.md)为准。

```sh
corepack pnpm dev:check
corepack pnpm dev:all
corepack pnpm db:dev check-data --domain links
corepack pnpm db:dev seed-data --dataset link-v1
corepack pnpm db:dev remove-data --dataset link-v1
```

补种和清理默认预览；写入需`--apply --confirm 数据库名`，先确认本机非生产目标并完成备份。清理还要求目标没有其他服务连接，保留用户修改、删除归属、跨业务引用及仍使用的媒体。开发启动不自动执行迁移、补种或清空。

内容包升级v6，明确包含links与linkSettings，兼容冻结的v1–v5；旧包不会清空友链规则。导入保持草稿，保留推荐、排序、日期和可选Logo，沿用预览、跳过/复制、目标变化检测、事务回滚及同票据核查。完整数据库与受管媒体备份保留状态、关系、规则和归属账本，恢复后旧页面不能继续向同编号内容写入。具体操作见[备份与恢复](../backup-and-recovery.md)。
