# 朋友圈内容维护

朋友圈使用现有后台媒体库及审计。删除动态时保留不可公开读取的提交记录，释放动态、评论头像的媒体引用并删除点赞；删除评论也保留提交记录，以拒绝旧请求重建内容。

## 内容包迁入

内容包从 v2 起包含 `moments`：正文、话题、图片、地点、设备、心情、文章/外链引用、置顶、原状态、创建/发布时间、删除标记和评论。当前导出 v3，同时增加留言，仍兼容 v1/v2。评论包含作者快照、正文、审核状态及删除标记。格式校验拒绝不支持的字段、重复编号、非法链接及包外文章引用。

旧 v1 内容包仍可读取，朋友圈集合视为空；旧导入票据也可重新预览。管理页同时显示朋友圈预览数量、执行结果和草稿入口。

迁入沿用“跳过相同内容”或“创建全部新副本”，不覆盖现有动态。新动态统一为草稿，文章关系映射到迁入的新文章或匹配的现有文章；不存在的引用使整个事务回滚。未删除评论保留原审核状态；删除评论不迁入。媒体清单、文件及引用在同一导入事务中处理，失败时清理本次新写入文件。重复执行同一票据返回已有结果。

内容包不迁入账号、访客身份、点赞及提交去重记录，新副本点赞为零。原公开/归档/删除状态在包中保留用于核查，迁入不会自动恢复公开。需要逐行恢复原始状态、互动与身份关系时，使用完整数据库备份。

## 完整备份

现有 `backup:full` 枚举数据库全部表并记录一致快照的行数与摘要，自动覆盖 `moment`、`moment_comment`、`moment_like` 和新增媒体引用关系。`backup:restore` 只恢复到新建的无网络 PostgreSQL 容器，核对全部表摘要、媒体字节，撤销恢复后的旧会话并轮换内容上下文；不会覆盖开发库。

隔离验证已覆盖 v1/v2 格式、朋友圈与文章关系映射、评论审核状态、媒体引用、新草稿、重复导入、故障回滚、原内容保留，以及完整快照的朋友圈正文、评论、点赞和去重记录摘要一致。完整恢复记录位于本机 `.backups/`；测试源码分别为后端 `tests/backup-integration.mjs` 与 `tests/full-backup-integration.mjs`。
