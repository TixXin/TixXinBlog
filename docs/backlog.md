## Git 内容仓库（静态发布的仓库为准用法）

状态：已调研，未排期。静态发布第一版已实现「后台为准」，本条目只保留尚未实现的「仓库为准」，记录于 2026-10-27。

### 背景

静态发布第一版从运行中的后端导出构建产物，写作仍在后台完成。希望进一步支持直接在 Git 仓库里写 Markdown，推送后由 CI 构建，不需要运行后端。

### 结论

- 内容格式只保留一套：仓库格式是内容包 v14 的文件化表达。文章、闪念、朋友圈用 Markdown 与 frontmatter，项目、友链、图库、图片提示词、平台订阅费和站点资料用 YAML，校验复用内容包格式。
- 同一站点只认一个事实源，不做双向同步。后台为准时可导出仓库；仓库为准时由 CI 构建，回到服务器部署时从仓库迁入。
- 稳定地址以地址而非数据库编号作为内容标识：闪念与朋友圈沿用 UUID；文章用自定义地址，没有时用当前数字编号，迁入时保留，历史地址一并导出。
- 写作工具用 VS Code 或 Obsidian；需要网页编辑时优先选 Sveltia CMS、Decap CMS 这类不绑定框架的 Git CMS。

### 待定问题

- 仓库为准时，图库媒体的入库与引用校验如何复用内容包的媒体映射规则。
- 从仓库迁入后台时，如何处理与既有数据库编号的冲突与历史地址。

## 站点时区设置（全站日期按站点时区分日）

状态：已确认方向，未排期。记录于 2026-11-05。

### 背景

全站按 UTC 分日：归档、闪念与朋友圈日历、活跃度热力图、留言统计、后台日期筛选等十余处，界面上标注“UTC”。当初是为了 SSR 与客户端分日一致。国内读者看到的“今天”从北京时间 8 点才开始。实时访问统计（“今日浏览”）已按北京时间切日，与其余 UTC 分日并存。

### 结论

- 做成站点设置“站点时区”，默认 `Asia/Shanghai`，不写死北京时间（项目对外开源）。
- 分日在后端按站点时区计算，或由后端随数据给出日期；前端只展示，不在浏览器按本机时区自行切日，保持 SSR 与客户端一致。
- 实时访问统计改为读取站点时区，与其余分日统一。

### 待定问题

- 修改时区后，已按旧时区汇总的按日统计（访问统计的每日行）是否重算，还是只影响之后的日期。
- 内容包是否携带时区设置（属于站点设置，倾向携带）。

### 第一步

列出全部按 UTC 分日或展示“UTC”的位置（前端 `timeZone: 'UTC'`、`toISOString().slice(0, 10)`、后端 SQL 的日期截断），确定统一的取日入口。

## 实时在线与访问统计的扩展

状态：已确认方向，未排期。记录于 2026-11-05。

### 背景

心跳版实时在线已上线：访客每 30 秒上报一次当前路径，后端用内存表记在线会话与所在页面（90 秒窗口，页面关闭时主动离开），博主 2 分钟内有心跳视为在线；按访客与路径 30 分钟去重计浏览，按北京时间汇总每日访客与浏览，底栏显示在线人数，站点统计卡片显示累计数字，文章页显示正在阅读人数。实现见 `src/backend/server-main/src/modules/presence/` 与前端 `useLivePresence`。

### 结论

第一期（文章页正在阅读、离开即下线、文章阅读量改为 30 分钟去重）与第二期（后台访问统计页：趋势、热门页面、来源域名、设备分布）已实现，契约见 [API 约定](api.md#实时在线与访问统计)，备份归属见[备份与恢复](backup-and-recovery.md)。剩余第三期。

- 第三期，博主状态：自定义状态文字与过期时间、隐身开关（在线但不对外显示），底栏博主卡片展示状态文字。站点资料已有手动状态类型、状态文案（≤20）与签名（≤60），在此基础上补过期时间与隐身。
- 隐私：不存 IP、完整 UA 或完整来源地址，访客标识沿用本地随机的 `blog-reader-id`。
- 不做：引入 Redis 或多实例计数；公开展示“谁在看哪个页面”（只在后台给博主看）；静态发布形态继续隐藏这些入口。

- 与[站点时区设置](#站点时区设置全站日期按站点时区分日)的先后：访问统计的分日应读取站点时区。

### 第一步

第三期先核对站点资料里现有的手动状态字段与内容包版本，再补状态过期时间与隐身开关。
