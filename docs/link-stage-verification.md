- `friend_link`提供稳定编号、名称、介绍、规范化URL、可选Logo、推荐、排序和发布状态；`link_settings`独立维护规则。推荐与上架独立，不表示已验证互链。
- `/links`及全站友链搜索走真实API；后台`/admin/links`、`/new`、`/:id`和`/settings`可维护内容及规则。公开只读上架且未删除记录，统计从实际公开明细计算。

- Logo支持受管图片、外部HTTPS地址或无图，两个来源互斥；更换和删除只释放当前引用。服务端不会访问填写的站点或外部Logo地址。

- 内容包v6显式包含links/linkSettings，严格兼容v1–v5。skip按规范地址跳过；copy可另建同址草稿，数据库限制同址同时只公开一条。旧包不清空新规则，迁入不自动上架。

## 联合回归修正

原生历史在页面水合前变化时，旧Nuxt启动地址可能覆盖实际历史槽位；固定版本补丁使原生目标在启动及SSG恢复阶段保留。图库、项目、友链和首页首帧使用SSR查询，挂载后接管真实URL并取消旧请求；首页还保留连续模式的SSR累积前缀。正式历史用例检查第二次原生返回与前进，不能仅以短暂显示正确URL判定通过。

Nuxt清单预取在页面卸载后仍可能执行，现保存定时器并在卸载/隐藏时暂停，恢复后按需重排；`beforeunload`只在尚未接管或确有待执行预取时短期监听。真实清单503与清缓存、业务结果、浏览器错误断言保持原样。安装、Docker和开发副本都使用同一补丁，维护方式见[补丁说明](../patches/README.md)。

连续加载取消请求不会重新抢回已经离开的文章路由；设置抽屉重复打开后恢复正确焦点；闪念编辑入口等身份恢复完成再开放，已经输入的内容继续保留。后台编辑恢复副本按账号、内容编号与恢复上下文隔离，跨恢复的旧输入可完整读取但不会绑定同编号新媒体。

验证前置同步改用真实API结果与用户操作：朋友圈筛选先核对实际非空内容；媒体跨页先等已登录用户菜单；连续加载先用小幅真实滚轮结束滚动恢复，再可靠定位末卡并观察真实哨兵和下一页请求。Dock负对照保留了程序滚动被恢复逻辑抢回的时序，原构建更换前置后三次通过；补验发现Firefox固定滚轮位移只到列表中段，最终统一为真实输入接管后定位，三浏览器各三主题全部通过。未放宽超时或修改产品。首页历史采样还补齐原生事件早于HTML节点创建时的空值保护，保留全部水合和页面异常断言。

依赖门禁发现`@nestjs/platform-express@11.2.3`仍解析到multer2.2.0，已仅对这一依赖路径固定2.3.0；未扩大其它依赖升级范围。原因见[官方2.3.0修复](https://github.com/expressjs/multer/releases/tag/v2.3.0)。更新后生产依赖审计无已知漏洞；真实独立依赖副本确认Nest解析2.3.0，269个后端源码摘要一致，构建及media、backup、project-backup、link-backup、unicode五组全部通过。最新三个Docker目标与容器联调也通过，本次标签、容器、卷、网络和环境目录已清理，95份历史备份清单保持不变。
