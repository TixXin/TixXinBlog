# 可靠启动与朋友圈真实业务验收

验收日期：2026-09-09。基于 Windows、Node 24.16.0、pnpm 9.15.0、PostgreSQL 16，使用独立端口、临时数据库、媒体目录、账号和生产构建副本。本文记录本阶段范围，不代表留言、项目、图库和友链已经实现真实管理。

## 实际行为

- 根目录 `corepack pnpm dev:check` 定位配置、数据库、迁移、端口、服务归属及同源 API 故障；`corepack pnpm dev:all` 启动或复用完整链路，等待真实就绪，退出只清理本次创建的进程。原开发命令保留。
- 朋友圈列表、详情、话题、搜索、UTC 日期、分页、点赞和评论均读取真实 API；作者资料复用站点配置，统计由公开内容计算。失败保留原画面和输入，提供重试，不回退 Mock。
- `/admin/moments` 支持发布、编辑、草稿、归档、置顶、删除、图片及评论审核/回复。媒体引用随事务更新。编辑使用版本校验与标签页恢复副本，创建和评论使用稳定提交标识。
- 三主题保留标题/正文独立过渡及作者/日历归属。认证 Cookie 轮换使用 keepalive 和有期限的跨文档协调，快速跳转后可恢复登录；未确认身份时不猜测评论身份，不同账号不串用草稿。
- 内容包导出 v2 并读取 v1，朋友圈迁入新草稿并映射文章、评论与媒体。完整备份恢复保留原始状态、点赞、评论和提交记录。
- `corepack pnpm db:dev` 提供只读状态、显式开发样本、样本清理、业务清空与事务重建。默认预览，写入需确认目标且先备份，清空拒绝其他服务连接，不自动清除磁盘媒体。

## 运行及边界

启动见[开发启动说明](development-runtime.md)，管理与恢复见[朋友圈业务](moment-business.md)、[数据工具](development-database.md)和[维护说明](backend/moment-maintenance.md)。日常启动不执行迁移、seed或清空。

实际浏览器测试使用Windows上的Playwright引擎，不能代替iOS/Android真机。Windows WebKit沿用已有字体截图等待兼容，仍检查真实字体请求及FontFace状态。完整链路冷启动在Windows实测，Linux生命周期在容器验证；Ubuntu全链路与数据库工具已配置CI入口，但本轮未推送或触发云端CI。

编辑恢复副本位于当前标签页sessionStorage，评论未发送输入有离开保护；它们不能代替服务器草稿或备份。关闭浏览器存储时仅保留当前会话能力，未执行真机隐私模式矩阵。认证协调标记不含凭据，旧文档请求中断后最长等待约10.5秒再确认Cookie状态；真实会话过期仍需要重新登录。

完整恢复已验证数据库及文件；本轮未使用 `RESTORE_API_IMAGE` 执行恢复容器内HTTP应用探针。真实对外推送、部署及发布内容不在本轮授权中。
