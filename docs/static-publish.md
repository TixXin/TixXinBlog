# 静态发布

静态发布把同一套 Nuxt 前端与三套主题预渲染成纯静态站点，部署到 EdgeOne、Cloudflare 等边缘平台，访问侧不依赖常驻服务器和数据库。写作仍在后台进行，构建时从运行中的真实后端读取公开数据。它不是另一个博客版本：页面、主题、内容格式与服务器部署完全相同。

适用场景与不采用的方案见[架构与代码入口](architecture.md)；已调研但尚未实现的部分（Git 内容仓库、访客互动）见[待办与已调研方向](backlog.md)。

## 它做了什么

一次构建按顺序完成，任何一步失败都不会产出缺页、空列表或零统计的站点：

1. 从真实后端读取文章、闪念、朋友圈、图库、项目、友链、提示词、订阅与站点资料的公开数据，生成预渲染地址清单（固定页面、订阅源，加上全部文章、标签、专栏、闪念、朋友圈与话题）。
2. `nuxt generate` 预渲染这些地址，并额外预渲染分页、归档年月、图库分类与照片、项目进展与标签与详情、友链推荐、提示词模型与详情、订阅币种、朋友圈与留言日期等页面状态。
3. 用真实浏览器打开这些页面，把页面在浏览器内取的数据导出为**冻结接口**文件（`/_api/<哈希>.json`），同时导出受管媒体的原图与全部宽度变体、订阅图标。
4. 删除 SPA 回退与预压缩副本，写入 Cloudflare 的 `_headers`、`_redirects` 与 EdgeOne 的 `edgeone.json`。
5. 断开回源，再用真实浏览器把同样的地址访问一遍，确认没有缺失文件、失败请求、脚本错误或请求失败卡片，并核对文件数与单文件大小在平台限制内。

构建完成后，站内直接打开与站内切页都不再请求 `/api/v1`：页面数据来自预渲染的 Nuxt payload，查询参数变化后的数据来自冻结接口。

## 构建前准备

- 运行中的后端，且目标站点已完成初始化、有真实内容。构建不会写数据库，也不会迁移或补种。
- Node >=26 <27 与 pnpm 9.15.0，仓库根执行 `corepack pnpm install --frozen-lockfile`。
- 站点正式域名：canonical、站点地图与订阅源都按它生成。

## 构建

```sh
corepack pnpm static:build --site-url https://blog.example.com
```

可选参数：

| 参数       | 默认值                         | 说明                                                      |
| ---------- | ------------------------------ | --------------------------------------------------------- |
| `--api`    | `http://127.0.0.1:3457/api/v1` | 公开接口基址，构建期间只发起 GET                          |
| `--locale` | `zh-CN`                        | 界面语言，只接受 `zh-CN` 或 `en`，构建后访客不能切换      |
| `--theme`  | `nexus`                        | 布局主题，必须是已登记的主题（`nexus`、`aurora`、`dock`） |
| `--out`    | 前端 `.output-static/`         | 输出目录，**每次构建会先清空**                            |

产物位于 `<out>/public`，可直接部署；同目录还有 `static-report.json`（页面数、文件数、体积、校验结果、上游失效图标）与 `frozen-api-manifest.json`（冻结接口文件与原始请求键的对应关系，用于排查）。

构建耗时的主要部分是预渲染（文章页要做 Markdown 与代码高亮渲染）与两轮浏览器访问。文章页并发固定为 4：默认并发会让详情请求超时，预渲染失败会直接中止构建。

本机预览产物：

```sh
corepack pnpm static:serve --root src/frontend/web-blog/.output-static/public --port 4310
```

它按静态托管的规则返回文件：目录取 `index.html`，未知地址返回 `404.html`。

## 静态站的行为差异

| 能力             | 服务器部署                   | 静态发布                                                     |
| ---------------- | ---------------------------- | ------------------------------------------------------------ |
| 文章、列表与详情 | 请求 `/api/v1`               | 预渲染 payload 与冻结接口文件                                |
| 分页与筛选       | 服务端查询                   | 预渲染的常见组合；未枚举到的组合在列表全量上计算             |
| 全文搜索         | 服务端 `ilike` 匹配          | 在列表全量上做子串匹配，文章只匹配标题、摘要与标签，不含正文 |
| 访客互动         | 评论、点赞、浏览、留言、回应 | 全部隐藏，不发起请求                                         |
| 友链申请         | 按后台开关开放               | 隐藏                                                         |
| 登录与初始化     | 后台登录、`/setup` 向导      | 不请求认证与初始化接口，产物不含 `/admin` 与 `/setup`        |
| 主题与界面语言   | 访客可切换，按 cookie 渲染   | 构建时固定，外观设置里隐藏两处切换                           |
| 未知地址         | Nuxt 错误页                  | 平台返回 `404.html`                                          |
| 安全头           | Nitro `routeRules`           | `_headers`（Cloudflare）与 `edgeone.json`（EdgeOne）         |

颜色模式（深色/浅色）与阅读设置只存本机，静态站照常可用。

`feed.json`、`rss.xml`、`atom.xml`、`flash.xml`、`moments.xml`、`/api/flash.json`、`/api/moments.json`、`sitemap.xml` 与 `robots.txt` 都在构建时生成，内容来自同一批真实数据。

## 部署

产物是纯静态文件，两种平台的配置都已生成：

- **Cloudflare Pages / Workers 静态资源**：上传 `<out>/public`，自动读取 `_headers` 与 `_redirects`。
- **EdgeOne Pages**：上传 `<out>/public`，自动读取 `edgeone.json`（重定向与安全头）。

发布前复核平台的当前限制（价格、额度和版本会变，按官方页面核对）。核实于 2026-10-27 的数值：EdgeOne Pages 免费版单项目最多 2 万个文件、单文件最大 25MB、总存储 5GB，`edgeone.json` 最多 100 条重定向与 30 条响应头；加速区域含中国大陆时域名需要 ICP 备案。Cloudflare Workers 免费版每天 10 万次请求，R2 免费 10GB 且出站流量不计费。

本机开发库的产物规模记录在 `static-report.json`（约 1.4 千个文件、50MB 量级）；超过限制时优先考虑把媒体迁到对象存储。

`/articles` 到首页的 301 重定向由 `_redirects` 与 `edgeone.json` 表达；历史地址重定向尚未导出，迁移部署形态后旧链接会失效，需要另行处理。

## 已知限制

- 访客互动全部关闭，未接第三方评论服务；需要互动时继续使用服务器部署。
- 静态产物是构建时数据的快照。内容更新后必须重新构建并重新部署，后台改动不会自动生效。
- 订阅图标来自平台抓取缓存，上游失效时服务器部署同样返回 404；构建会把这些地址记入 `static-report.json` 的 `upstreamMissing`，页面改用默认图标。
- Git 仓库作为内容事实源（直接写 Markdown、推送后由 CI 构建）尚未实现，当前只有「后台为准」一种用法。

## 验证

- 构建脚本自身的单元测试：`corepack pnpm --test scripts/static`（已纳入 `test:dev`）。
- 每次构建的最后一轮浏览器校验；失败时退出码非零，`static-report.json` 列出问题页面与原因。
- 改动静态发布相关代码后按仓库约定运行 `corepack pnpm check:local --e2e`。
