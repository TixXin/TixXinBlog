# 长文章章节定位

文章编辑页在“向正文插入媒体图片”下方提供“正文章节”。先选择标题，再点击“定位章节”，正文光标移到对应标题行首，正文输入框滚动到该行。重复标题通过行号区分；修改正文、载入恢复副本后，章节从当前正文重新计算。没有标题时显示真实空态。

实现使用现有 MarkdownIt 的标题 token 和源码行映射，支持 ATX、Setext、多行 Setext、嵌套引用及列表里的标题；围栏与缩进代码中的标题不会混入。源码位置按 textarea 的 LF 行尾计算，定位不回写正文。原生下拉框保留键盘选择能力，定位按钮与选择操作分开，窄屏允许自然换行。

## 实际检查与改动范围

改动前在 Nuxt 单元测试环境挂载真实 `PostEditor`，注入包含 200 行中文正文的文章：正文输入和预览存在，但没有章节选择控件，章节定位交互测试实际失败。长文后半部分只能依赖正文滚动或浏览器查找；同名标题没有源码行号入口。此检查没有访问或写入日常数据库。

新增定位只调用原生 focus、setSelectionRange 和滚动，不替换 textarea 节点、不重写 value、不触发 input/change 或保存事件。长段落折行的高度通过临时、不可见的同排版文本测量，测量节点当次移除。输入法合成期间禁用导航；不会在正文输入过程中自动移动光标。保存请求所有权、版本冲突、自动保存、恢复副本与实时预览沿用原实现。

## 验证入口与边界

- `tests/unit/postOutline.test.ts`：Markdown 语义、重复标题、CRLF/CR 与中文位置、未闭合围栏、多行和嵌套标题、超过 50,000 字符的长文。
- `tests/unit/postOutlineEditor.test.ts`：挂载实际编辑器，检查节点和正文保持、选区定位、保存期间门禁、合成事件、恢复替换与空态。
- `tests/e2e/post-outline.spec.ts`：隔离服务使用 80 节长文，覆盖 320、390、760、761、800、801、1440px；检查折行滚动、首尾定位、原生撤销重做、合成事件、刷新恢复与原有自动保存。截图由测试输出目录保留在 `.playwright-mcp/`。

单元验证命令：`corepack pnpm --filter web-blog test tests/unit/postOutline.test.ts tests/unit/postOutlineEditor.test.ts`。浏览器回归由统一构建后的 `corepack pnpm test:e2e:run post-outline.spec.ts` 执行，只允许现有隔离测试运行器。

本批还在 Chromium、Firefox、WebKit 的独立原生 textarea 中直接执行实际定位辅助函数，使用约 84,000 字符正文与 280/650px 两种输入宽度。六种组合均能定位至后半部分、回到行首，正文未变且没有额外 input 事件，临时测量节点均移除；原生撤销与重做记录保留。该检查不启动业务服务、不访问数据库。原始本地产物位于 `.artifacts/sustainable-blog/writing-navigation/native-helper.json`，它不替代真实管理页的完整 E2E。

本批未实施预览性能优化，也未将有限开发基线解释为生产收益。DOM 单元环境不验证排版坐标或浏览器原生撤销记录；这些由浏览器回归检查。合成事件回归不能替代真实系统输入法、系统辅助技术或真机验收。日常长文样本由统一开发数据批次补齐，不通过此组件测试写入日常数据库。
