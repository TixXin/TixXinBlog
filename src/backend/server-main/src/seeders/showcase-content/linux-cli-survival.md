上个月团队来了两个实习生，第一天就被服务器上的命令行吓到了：登录上去一片黑，想看个日志不知道文件在哪，想停个进程不知道怎么找。我花了一个下午带他们过了一遍日常用到的命令，发现自己其实也从来没有系统整理过这些东西，都是七八年里一点一点攒下来的肌肉记忆。

所以干脆写下来。这篇不追求全面，只列我在日常开发和部署里真正天天用的命令，每条都配一个实际场景，先知道“什么时候用”比背参数重要得多。环境以 Ubuntu 22.04 为准，macOS 大部分也通用。

## 先学会不迷路

刚上服务器最常见的恐慌是不知道自己在哪、有什么。四个命令解决：

```bash
pwd                    # 我在哪
ls -lah                # 这里有什么，含隐藏文件，大小用人能看懂的单位
cd /var/www/blog       # 去某个地方
cd -                   # 回到刚才的地方
```

`ls -lah` 里三个参数我建议当成一个整体记：`l` 是列表，`a` 是包括 `.env` 这种以点开头的文件，`h` 是把 `4096` 显示成 `4.0K`。新手最容易漏掉 `a`，然后对着“明明有 `.env` 为什么看不到”发呆。

`cd -` 是我用得最多却最少被教的命令，在两个目录之间来回跳的时候非常省事。再配一个 `cd` 不带参数直接回家目录，基本就够了。

## 找文件和找内容

场景：知道有个配置文件叫 `nginx.conf` 之类的，不知道在哪。

```bash
find /etc -name 'nginx*.conf' 2>/dev/null
```

`2>/dev/null` 是把“权限不够”这类报错扔掉，否则输出里一半是红字。如果是找内容而不是找文件名，用 `grep`：

```bash
grep -rn 'DATABASE_URL' /var/www/blog --include='*.env*'
```

`r` 递归，`n` 显示行号，`--include` 只看某类文件。我在排查线上环境变量问题时这条命令一天能敲十几次。如果服务器上能装软件，`ripgrep`（命令是 `rg`）比 `grep` 快得多而且默认忽略 `.gitignore` 里的东西，值得第一时间装上。

## 看日志

这是实习生问得最多的事。日志文件通常很大，不要用 `cat`，会刷屏刷到你怀疑人生。

```bash
tail -n 200 /var/log/nginx/error.log      # 看最后 200 行
tail -f /var/log/nginx/access.log          # 盯着实时输出，Ctrl+C 退出
less +G /var/log/syslog                    # 从末尾开始翻，q 退出
journalctl -u blog-api -n 100 --no-pager   # systemd 服务的日志
```

`less` 里按 `/` 可以搜索，按 `n` 跳到下一个匹配，按 `G` 到末尾，`g` 到开头。学会 `less` 之后基本就不需要把日志下载到本地再打开了。

一个实用组合是把 `tail -f` 和 `grep` 接起来只看错误：

```bash
tail -f /var/log/nginx/access.log | grep --line-buffered ' 50[0-9] '
```

`--line-buffered` 很关键，不加的话 `grep` 会攒一批再输出，你以为没有错误其实是还没刷出来。

## 进程和端口

场景：部署新版本的时候报 `EADDRINUSE`，端口被占了。

```bash
ss -lntp | grep 3000          # 谁占着 3000 端口
ps aux | grep node            # 所有 node 进程
kill 12345                    # 先礼貌地请它退出
kill -9 12345                 # 它不听话再强制
```

`ss` 是新一代的 `netstat`，参数 `lntp` 分别是监听中、数字端口、TCP、显示进程名。看到 PID 之后再去 `kill`。强调一下 `kill -9` 不是默认选项，它不给进程任何清理的机会，数据库连接、临时文件都可能留下烂摊子，先用普通 `kill` 等几秒。

`htop` 比 `top` 好看得多，能用方向键选进程直接 kill，装上就不想回去了。

## 磁盘空间

场景：半夜告警磁盘 95%，要找出谁吃了空间。

```bash
df -h                              # 每个挂载点还剩多少
du -sh /var/log/* | sort -rh | head -20   # 哪些目录最大
```

`du -sh` 是算目录总大小，`sort -rh` 按人类可读的大小倒序排，`head` 只看前二十。我们上次的元凶是 Docker 的构建缓存，`docker system df` 一看占了 40 多 GB，`docker builder prune` 之后世界清静。另一个常见嫌疑是 `journalctl` 的日志，用 `journalctl --vacuum-size=500M` 限制一下。

## 权限

新手最容易卡住的地方。核心就三件事：文件属于谁、谁能读写执行、你是谁。

```bash
ls -l deploy.sh            # 看权限和归属
chmod +x deploy.sh         # 让它可执行
chown -R www-data:www-data /var/www/blog/uploads   # 把目录交给 web 用户
whoami                     # 确认自己的身份
```

`sudo` 不是万能药。见过好几次有人遇到权限报错就一路 `sudo`，结果文件全变成 root 的，Node 进程以普通用户跑反而写不进去。正确的做法是搞清楚服务是以哪个用户运行的，把目录的归属改给那个用户。

## 传文件和远程

```bash
scp -r ./dist user@server:/var/www/blog/     # 复制目录上去
rsync -avz --delete ./dist/ user@server:/var/www/blog/dist/   # 增量同步
ssh -L 5433:localhost:5432 user@server       # 把远程数据库端口映射到本地
```

`rsync` 比 `scp` 好的地方是只传有变化的文件，`--delete` 会把目标里多出来的文件删掉，正好适合部署静态产物。注意路径末尾的 `/`，有和没有的语义不一样：`dist/` 是把目录里的内容同步过去，`dist` 是把目录本身同步过去，第一次用很容易多出一层目录。

端口转发那条是我连线上数据库的标准姿势，不用在防火墙上开 5432，本地用 `localhost:5433` 连就行，关掉 SSH 就断了，很安全。

## 管道和重定向

上面已经偷偷用了好几次 `|`，这里正式说一下。管道把前一个命令的输出交给后一个命令当输入，Linux 命令行的大部分威力都来自这个机制。比如统计今天访问量最高的十个 IP：

```bash
grep "$(date +%d/%b/%Y)" /var/log/nginx/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10
```

拆开看就是：筛出今天的行，取第一列的 IP，排序，合并相同行并计数，按计数倒序，取前十。每一段单独都很简单，接起来就是一个小型的分析脚本。新手不用一次记住 `awk`，先记住“输出可以接着往下传”这个思路就够了。

重定向是把输出写进文件：`>` 覆盖，`>>` 追加，`2>&1` 把错误输出也一起带上。部署脚本里我一般这样写，让日志既能在终端看到又留档：

```bash
./deploy.sh 2>&1 | tee -a /var/log/deploy.log
```

`tee` 像一个三通，一边往屏幕打，一边往文件写。排查线上问题的时候把这条日志翻出来，比凭记忆复述“我当时好像看到一个报错”靠谱得多。

## 几个救命的习惯

**用 `history | grep` 找以前敲过的命令。** 上周敲过的那条很长的 `docker run` 不用重新想，`history | grep 'docker run'` 就出来了。配合 `Ctrl+R` 反向搜索更快。

**危险命令先加 `echo` 或 `--dry-run`。** `rm -rf` 之前先 `ls` 一下要删的路径；`rsync --delete` 之前先加 `--dry-run` 看看它打算删什么。我至今记得三年前一个空格打错把整个 `~/projects` 删掉的下午。

**长任务用 `tmux`。** SSH 一断，前台跑的命令就死了。`tmux new -s deploy` 开一个会话，断线后 `tmux attach -t deploy` 接回来，构建还在跑。

**别记参数，记场景。** 这篇里的每条命令我都是先有“我要看最后两百行日志”这个需求，才去记 `tail -n`。遇到新场景就查一次 `man` 或者 `--help`，用三次就记住了。

两个实习生现在已经能自己上服务器查日志、重启服务了，上周其中一个还反过来教我 `ss -lntp` 的输出可以用 `-H` 去掉表头。命令行这东西没有什么门槛，就是需要有人告诉你“先从这十几条开始”，剩下的会自己长出来。
